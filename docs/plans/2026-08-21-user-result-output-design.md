# 用户结果输出目录设计

## 目标与边界

Model PK 继续把 `~/.dsh/model-pk/...` 作为内部事实来源：其中保存冻结输入、完整事件、模型请求证据、内容寻址对象和不可变封印，服务于复现、审计、统计与分析。普通用户不需要理解这套目录，也不应把它当成交付结果。

创建页将目录拆成两个独立概念：

- **项目起始目录（可选）**：只读输入。已有项目会被冻结并复制到每个 Attempt；不选择时，每个模型从内部空白工作区开始。
- **结果输出目录（必填）**：用户拥有的交付根目录。每次实验在其中创建独立、易读的子目录，不覆盖已有文件。

内部归档仍是唯一可信记录。用户输出是从归档派生的便利副本；删除内部实验时不删除用户已经导出的结果。

## 数据流与目录结构

Draft 保存经过 `realpath` 解析并验证可写的 `resultRootPath`。Preflight 冻结该路径和草稿 revision；Start 使用任务名、时间及实验短 ID 计算唯一 `resultPath`，并把它写入 Experiment。这样重试 Attempt 始终进入同一次实验的结果目录，而新实验不会与旧结果冲突。

建议结构：

```text
<resultRoot>/
└── <任务名>-<YYYYMMDD-HHmmss>-<短ID>/
    ├── 对照结果.md
    ├── 01-<模型名>/
    │   ├── result.md
    │   └── attempts/001-result.md
    └── 02-<模型名>/
        ├── result.md
        └── attempts/001-result.md
```

每个 Attempt 内部归档成功后，原子写入不可变的 Attempt 结果，并更新该模型的 `result.md`。实验进入 `SETTLED` 后生成聚合的 `对照结果.md`。输出失败必须显式展示，不能把内部归档成功伪装成用户交付成功；但用户目录故障不改变模型执行事实和内部归档。

代码工作区默认不自动复制，以避免大型仓库重复占用磁盘。终态 Attempt 提供“导出工作区”操作，从内部 `workspace-manifest.json` 和对象库安全物化到对应模型目录的 `workspace-attempt-NNN`，目标已存在时拒绝覆盖。

## 安全、兼容与交互

结果根目录必须存在、是普通目录、可写，并且不能位于 Model PK 内部数据根目录。生成的实验和模型目录名经过清洗；写文件采用临时文件加原子重命名。显式导出工作区永不覆盖已有目标，失败后清理临时目录。

旧 Draft 缺少结果目录时按 `null` 读取并要求用户选择；旧 Experiment 缺少 `resultPath` 时继续允许查看，并将打开操作回退到内部归档。新实验的“打开文件夹”和“打开结果目录”只打开用户结果路径；内部路径仅保留在高级诊断与存储实现中。

验收标准：纯写作不再要求空白起始目录；结果目录未选择时不能预检；两路成功输出能在用户目录直接找到；同名模型与重试不会相互覆盖；工作区可显式导出；内部归档、封印和现有实验删除语义不变；macOS 与 Windows 的目录选择继续共用原生选择器。
