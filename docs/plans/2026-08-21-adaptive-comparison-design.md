# 自适应结果对照设计

## 目标

实验页不再对所有任务一律展示模型最终回复的双栏对照。系统根据每个 Attempt 的实际工作区变化，在文本对照与工程对照之间自动切换。

## 判定规则

- 最终工作区相对起始快照没有文件变化：使用模型最终文本回复进行对照。
- 恰好新增或修改一个不超过 1 MiB 的 UTF-8 文件：使用该文件的真实内容进行对照。
- 删除文件、产生多个文件、单文件为二进制或过大：判定为工程结果，不提供无意义的文本双栏。
- `.model-pk-ready` 等插件内部文件不计入用户变更。
- 旧实验没有工作区摘要时继续按最终文本展示，保持可读性。

## 数据流

Attempt 收尾时已有最终 `workspace-manifest.json`。归档模块将它与冻结的 baseline manifest 比较，生成有界的文件变更摘要；单文本文件在归档前从隔离工作区读取内容。归档模块同时从 transcript 中只汇总 `assistant/chunk` 的 usage 事件，避免与 `assistant/message` 的重复 usage 双计。

摘要随 Attempt projection 持久化，实验页无需再次读取磁盘：文本结果显示可勾选的对照入口；工程结果显示新增、修改、删除数量、变更文件列表、耗时、Token、错误和工作区导出入口。

## 边界

- 变更文件列表最多返回 200 项，并保留完整计数与截断标记，避免超大仓库拖垮 Web RPC。
- 第一版不自动猜测并执行测试命令；界面明确标记“验收测试未配置”。后续可单独增加冻结的验收命令配置。
- 用户结果目录和内部证据归档结构保持不变。

## 验证

- 单元测试覆盖无文件、单文本、单二进制、多文件、删除和 Token 汇总。
- 归档测试验证摘要随 Attempt 收尾生成。
- 客户端测试验证文本结果保留勾选入口，多文件结果隐藏入口并展示工程摘要。
